# Android: исходящие ссылки в другие приложения

Запрос владельца 07.11.2026: открывать другое приложение по ссылке, как в Chrome.
Реализация подготовлена в `feat/quick-search`; GitHub Actions запрещены и не используются.

`ExternalApps.kt` отделяет безопасный разбор от запуска. Входящий фильтр DefaultBrowser
в PageTools.kt не ослаблен. Новые обработчики обычной/приватной сессии и попапа стоят до
переключения UA, чтобы не терять исходный trusted gesture. Subframe и hidden-window handoff
блокируется. Клик из iframe с target=_top/_blank может породить top-level запрос;
такой источник не определяется надёжно по triggerUri и не заявляется абсолютно запрещённым.
Он проходит ту же проверку trusted gesture/видимости и явное подтверждение. Перед запуском есть подтверждение, повторная проверка видимости и жизненного цикла.
Запускаемый Intent создаётся заново; поля исходного intent не копируются. Секретные URI не логируются.

Переходы с HTTP302 поддерживаются только при сохранённом Gecko hasUserGesture. Если движок
теряет этот признак, автоматического восстановления жеста по времени нет: запуск отклоняется.
Для обычного веб-адреса предусмотрена явная команда меню «Открыть в приложении» с системным
выбором специализированных обработчиков. Приложение не определяется как отсутствующее лишь
по пустому queryIntentActivities: custom scheme запускается после подтверждения с обработкой
ActivityNotFoundException/SecurityException. HTTP(S)-chooser имеет узкие manifest queries.

Сопутствующие подтверждённые исправления: MainActivity list/tile возвращает сохранённую
обычную вкладку профиля; onDestroy очищает contentBlockingDelegate, не закрывая живые сессии;
Diag.redact удаляет чувствительные части URI и email из обоих выходов (UI + logcat).

Подготовлены ExternalAppsTest (11 случаев), DiagPrivacyTest (4 случая), расширена живая
приёмка profile-retention.sh: ожидание load/ready/focus/value, прокрутка до профиля,
возврат с главного экрана в режиме списка и плиток. Имеющиеся проверки loads==1/черновика
сохранены. В i18n — три новых строки на 16 языках; восстановлено покрытие 44 существующих
Windows-ключей в метаданных i18n-new. Проверка docs/i18n-new/check.py: PASS.

Корень выполнил локальную сборку исходного freeze: 24 XML-suite, 2370 unit-тестов,
0 failures/0 errors; debug APK собран. После этого внесена точечная совместимость:
обычные javascript: ссылки оставляются движку Gecko, а javascript внутри intent по-прежнему
запрещён для запуска приложения. Добавлен отдельный regressiontest; эта последняя правка
требует короткой повторной сборки/прогона корнем. Реальная device/UI-приёмка ещё не завершена.
Публикацию/выпуск выполняет только корень.

Открытый отдельный дефект: Tabs.add/update/read Android сохраняют исходные login URL
в preferences. Защита живой сессии не устраняет повторное открытие такого URL после завершения
процесса. Безопасное исправление требует разделения живого исходного адреса и сохраняемого
snapshot + миграции, с доказательством «явно открытый login выполняется один раз, после
перезапуска не повторяет SMS». Эта задача здесь не отмечается выполненной.
