# Android: сохранение страницы при переключении профилей

Запрос владельца 07.11.2026: переключение профилей не должно обновлять страницу и сбрасывать работу.

Причина в коде: общий LRU в `Gecko.session()` закрывал сессии после превышения
`Settings.keepAlive` (по умолчанию шесть). Даже последняя страница другого профиля могла быть закрыта.
Возврат создавал новый документ.
Дополнительно переключатели направляли обычные вкладки на закреплённую страницу
другого профиля: выбранная вкладка запоминалась только глобально. Теперь её идентификатор
хранится отдельно для каждого профиля; переключатель и список профилей возвращают её. Если все страницы были страницами входа, прежний fallback
также закрывал одну из них вопреки защите входа.

Изменение: последняя выбранная сессия каждого профиля и страницы входа не участвуют
в автоматической выгрузке. Остальные сессии освобождаются от старых к новым до мягкого лимита.
Закрытие вкладки, очистка данных и удаление профиля по-прежнему закрывают соответствующие сессии.
Cookies остаются изолированы по contextId; сервер для этого исправления не используется.

Проверки:
- `SessionRetentionTest`: более шести профилей, выбор фоновой вкладки, порядок LRU,
  все страницы защищены, удалённая защита.
- `.github/scripts/profile-retention.sh` в `acceptance.yml`: семь настоящих страниц
  GeckoView на loopback-сервере, ввод текста, возврат без URL, проверка ровно одной загрузки
  каждого документа и сохранения текста; семь скриншотов и JSON-состояние; два обычных черновика и настоящий выбор профиля через UI в результатах приёмки.
- Сборка и Android-тесты выполняются только GitHub Actions: сначала `build.yml`, затем `acceptance.yml`.

Ограничение: защита относится к живому процессу. После завершения процесса Android, падения
движка или явной очистки данных повторная загрузка возможна. Лимит памяти становится мягким:
при большом количестве профилей защищённые сессии могут превысить выбранное число.

Статус: подготовлено; CI и приёмка ещё не завершены. В main не влито.
