# Ось Browser — техническое задание (главная сессия)

Этот документ — главный источник правды для продолжения проекта. Новая сессия
начинает отсюда. Читать целиком перед работой.

## 1. Что это и зачем
**Ось Browser** — деловой браузер для Android. Позиционирование на всех этапах:
- **деловой браузер** (business browser);
- **главная сила — конфиденциальность** (privacy-first);
- мультипрофиль — лишь одна из функций, не основная;
- по меню, виду и удобству должен **превосходить Chrome и Opera**;
- всё по современным подходам к безопасности и удобству.

Фирменный стиль: тёплый **алый** акцент (не бирюзовый). Имя — «Ось Browser».
Логотип — кольцо «О» на оси с точкой слева и квадратом справа.

## 2. Репозиторий, сборка, релизы
- Репозиторий: `basilsolanji-hash/Browser`, ветка `main`.
- Язык: Kotlin. UI строится **программно, без XML-layout** (важно — соблюдать стиль).
- Движок: **GeckoView** (`latest.release`, сейчас Firefox 158, требует compileSdk 37).
- Сборка только в **GitHub Actions** (локально нет Android SDK; maven Google/Mozilla
  заблокирован). Workflow: `.github/workflows/build.yml`.
  - Собирает **APK и AAB** (AAB — для Google Play), подписывает релизным ключом
    (секрет `KEYSTORE_PASSWORD` расшифровывает `app/release.jks.enc`), публикует в
    Releases. `versionCode` = номер прогона CI; `versionName` = `0.8.<run>`.
  - При ошибке компиляции пишет её текстом в комментарий к коммиту:
    `gh api repos/basilsolanji-hash/Browser/commits/<SHA>/comments --jq '.[].body'`.
- GitHub API: только REST (`gh -R basilsolanji-hash/Browser ...`); GraphQL и скачивание
  логов/артефактов заблокированы.

## 3. Жёсткая приёмка (ОБЯЗАТЕЛЬНО после каждого этапа)
- Workflow: `.github/workflows/acceptance.yml` + `.github/scripts/acceptance.sh`.
- Запуск: `gh workflow run acceptance.yml -R basilsolanji-hash/Browser --ref main`.
- Поднимает эмулятор Android (API 34), ставит debug-APK, прогоняет сценарии, делает
  скриншоты и логи, **пиксельно проверяет экраны на «белый/пустой»** (при пустых —
  сборка падает). Результаты force-push в ветку `acceptance-results`.
- Забрать результаты:
  `git clone --depth 1 -b acceptance-results https://github.com/basilsolanji-hash/Browser.git <dir>`
  затем смотреть PNG через инструмент чтения изображений и `diag.txt`/`logcat.txt`.
- Debug-сборка имеет `applicationId` с суффиксом `.test` и ABI x86_64 (для эмулятора);
  экраны `exported` только в debug (`app/src/debug/AndroidManifest.xml`).
- Сценарии запускаются через `am start` с экстрами:
  `--ei profile <n>`, `--es site <pinId>`, `--es url <url>`.

## 4. Архитектура (файлы в `app/src/main/java/ru/multibrowser/`)
- `App.kt` — Application: `Tr.apply`, `Settings.applyTheme`, `AppLock.register`.
- `MainActivity.kt` — список профилей (плитки + пилюли закреплённых вкладок), шестерёнка.
- `BrowserActivity.kt` — экран браузера: тулбар (чип профиля, полоса вкладок, ⋮),
  адресная строка (сверху/снизу), нижняя панель действий, свайп-обновление,
  авто-скрытие панелей, инкогнито, масштаб, меню, история, очистка, диагностика.
- `SettingsActivity.kt` — настройки (секции: закреплённые вкладки, язык, тема, поиск,
  конфиденциальность и безопасность, панели, адресная строка, полоса профилей,
  вкладки в памяти, количество профилей, названия профилей, данные).
- `Gecko.kt` — один GeckoRuntime; сессии по ключу `profileId:pinId`; contextId на профиль
  (изоляция cookies/хранилищ); UA-подмена только для mail.google.com; защита от трекеров
  (стандартный уровень); масштаб через fontSizeFactor; приватные сессии; `loadUrl()`
  с рендером локализованной стартовой страницы для маркера `os:start`.
- `Profiles.kt` — профили (имя/цвет/email/непрочитанные), последний URL на вкладку.
- `Pins.kt` — закреплённые вкладки (настраиваемые; по умолчанию одна «Старт» = `os:start`).
- `Search.kt` — выбор поисковика (по умолчанию DuckDuckGo — приватный).
- `Themes.kt` — 6 тем (Scarlet Dark/Light, Graphite, Sand, OLED, System) + палитра.
- `Ui.kt` — текущая палитра, helpers (rounded/oval/icon/iconButton/edge-to-edge, RTL).
- `Tr.kt` — переводы интерфейса, **10 языков** (en, ru, es, pt, fr, de, ar(RTL), hi, tr, zh).
- `AppLock.kt` — блокировка по отпечатку/PIN, FLAG_SECURE.
- `History.kt`, `DownloadLog.kt`, `Bookmarks.kt` — локальные хранилища (JSON в prefs).
- `StartPage.kt` — локализованная стартовая страница (под язык и тему, RTL).
- `Downloads.kt` — сохранение файлов в «Загрузки/Ось» + запись в `DownloadLog`.
- `Diag.kt` — журнал загрузки для меню «Диагностика».
- Ресурсы: `res/values(+-night)/colors.xml`, `themes.xml`, `drawable/ic_*` (векторы),
  `mipmap-anydpi-v26/ic_launcher.xml`.

## 5. Обязательные соглашения
1. **Все видимые строки — только через `Tr.t("ключ", аргументы)`** и переведены на все
   10 языков (полный список элементов в `Tr.M`, позиция ru = индекс 2 — списки не короче).
   Никаких новых строк на русском прямо в коде.
2. Цвета — только из `Ui.*` (палитра темы). Новые экраны — в стиле существующих
   (программный UI, `Ui.rounded/oval`, секции `sectionTitle`, диалоги AppCompat).
3. RTL: корневой layout уже разворачивается в `applyEdgeToEdge` для арабского.
4. Атрибуция коммитов (в конце сообщения коммита):
   `Co-Authored-By: Claude <noreply@anthropic.com>` и строка `Claude-Session: <url>`
   текущей сессии. Модель/идентификатор модели в артефакты не писать.
5. **Не имитировать бэкенд.** Функции, требующие сервера, делать локально или помечать
   как требующие отдельного проекта (см. §7).
6. После каждого этапа — **жёсткая приёмка** (§3) и фикс всех найденных багов.
7. До 3 субагентов (разрешено пользователем) — см. §8.

## 7. Осталось сделать (с критериями приёмки)
Приоритет — удобство меню и конфиденциальность. Для каждого пункта: реализовать +
перевести на 10 языков + пройти приёмку.

**A. Меню и вкладки (№15–19, частично есть основа).**
- Меню действий: Новая вкладка, Поиск, Новая вкладка инкогнито, Новая группа вкладок,
  Закрыть все вкладки, Выбрать вкладки.
- Группы вкладок (№15); сетка открытых вкладок квадратами (№16); поиск по вкладкам (№17).
- Приёмка: открыть/закрыть/сгруппировать вкладки, переключение, пустые состояния.

**B. Избранное и загрузки (№21, 22, 29) — хранилища `Bookmarks`/`DownloadLog` готовы.**
- Экран «Избранное» с папками (добавить/удалить/переименовать/переместить/создать папку);
  кнопка «В избранное» в меню браузера.
- Экран «Загрузки»: список, открыть/поделиться/удалить, очистить.
- Приёмка: добавить закладку, открыть из списка; скачать файл, увидеть в списке, открыть.

**C. Настройки сайтов и безопасность (№12, 13, 30, 31, 32).**
- Настройки сайта (по домену) и разрешения (камера/микрофон/геолокация/уведомления/
  всплывающие) — через `PermissionDelegate` + удобный экран разрешений.
- Проверка безопасности для пользователя (№31): HTTPS, выданные разрешения, статус
  блокировки, трекеры.
- Поиск в настройках (№32).

**D. Удобство (№26, 27, 28, 34, 35, 36-фраза).**
- Браузер по умолчанию (№26): intent-filter VIEW/BROWSABLE + подсказка «сделать
  браузером по умолчанию».
- Главная страница (№27): выбор стартовой страницы.
- Уведомления (№28): Web Push по профилям (требует проектирования; на GeckoView —
  `WebNotificationDelegate`).
- Режим чтения (№34): GeckoView reader mode; Сохранённые страницы (№35): офлайн-сохранение.
- Позитивная неповторяющаяся фраза при открытии (№36, без погоды) — локально.

**E. О приложении, справка (№23, 25).**
- «О приложении» + другие продукты (№23); Справка и отзывы (№25, отзыв — письмо/форма).

**F. Выделение текста (№37, локально).**
- При выделении текста: копировать + базовые действия + наша фишка «Добавить в заметку»,
  заметки сохраняются локально (в «личном кабинете» на устройстве).

**G. Сквозное (№2, 4, 5).** Довести меню/вид до уровня выше Chrome/Opera; современные
подходы; на все вопросы — логично и безопасно.

## 8. Требует решения пользователя (бэкенд) — НЕ имитировать
- №9 Личный кабинет (вход перед работой), №37 заметки с облачным сохранением,
  №36 погода города, №24 версия для ПК, №33 обучающая библиотека.
- Предложенный дефолт: **локально, на устройстве** (приватность, бесплатно, сразу).
  Для синхронизации между устройствами — отдельный серверный проект (нужны хостинг,
  БД, авторизация; составить отдельное ТЗ, в этой кодовой базе не разворачивать).

## 9. Субагенты (до 3)
Распараллеливать по независимым модулям, чтобы не было конфликтов правок:
- Агент 1 — реализация блока A (вкладки/группы) в своих файлах.
- Агент 2 — реализация блока B (избранное/загрузки) — отдельные экраны.
- Агент 3 — постоянная жёсткая приёмка (read-only + запуск acceptance, разбор скриншотов,
  поиск багов). Главная сессия сводит результаты, фиксит, собирает и релизит.
Не давать двум агентам править один и тот же файл одновременно.
