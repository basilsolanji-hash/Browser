# ТЗ: сервер os-browser.com (Beget VPS) — для новой сессии

## Исходные данные
- VPS Beget «os-browser», Ubuntu, СПб, публичный IPv4 **5.35.86.240**, 1 ГБ RAM, диск 10 ГБ
  (занято 2,9 ГБ). Доступ: `root@5.35.86.240`.
- Домен **os-browser.com** (+ www), почта **hello@os-browser.com**.
- Репозиторий **basilsolanji-hash/Browser**: сайт — `site/` (Astro, 10 языков, сборка
  `npm ci && npm run build` → `site/dist`), политика — `site/public/privacy.html` и `privacy-en.html`,
  материалы магазина — `docs/play/`. Релизы APK/AAB/EXE — GitHub Releases (`build-N`, `desktop-N`).
- Принцип проекта: приватность. Никакой аналитики, трекеров, сторонних счётчиков, cookies;
  логи без IP-адресов.

## Цель
Сайт https://www.os-browser.com работает с этого VPS: быстро, по HTTPS, с автообновлением из
GitHub при каждом слиянии в `main`, безопасно настроенный сервер, ссылки на скачивание ведут на
последние релизы.

## Задачи
1. **Безопасность сервера** (первым делом):
   - отдельный пользователь `deploy` с sudo; вход только по SSH-ключу; `PermitRootLogin no`,
     `PasswordAuthentication no`; при необходимости — другой порт SSH;
   - `ufw`: открыть только 22 (или новый порт SSH), 80, 443;
   - `fail2ban` для SSH; `unattended-upgrades` — автообновления безопасности;
   - пароль root, который владелец видел в панели, сменить и в чат **не присылать**.
2. **DNS** (в панели Beget, делает владелец по инструкции сессии): A-записи `os-browser.com` и
   `www` → 5.35.86.240; проверка `dig`.
3. **Веб-сервер**: nginx (или Caddy — на выбор сессии, с обоснованием):
   - отдаёт статический `site/dist` из `/var/www/os-browser`;
   - редирект `os-browser.com` → `https://www.os-browser.com` (или наоборот — одно главное имя);
   - HTTPS от Let's Encrypt (certbot с автопродлением), HTTP/2, HSTS;
   - сжатие gzip/brotli, кеш статики (immutable для файлов с хешем), правильные `Content-Type`;
   - заголовки безопасности: CSP без сторонних доменов, `X-Content-Type-Options`,
     `Referrer-Policy: no-referrer`, `Permissions-Policy`;
   - access-лог отключён или без IP (формат без `$remote_addr`), error-лог — только ошибки;
   - страница 404 сайта, `robots.txt`, `sitemap.xml` (если есть в сборке).
4. **Автодеплой**: GitHub Actions в репозитории — при пуше в `main` с изменениями `site/**`
   собрать сайт и выложить по SSH/rsync на VPS (ключ `deploy` — в секретах репозитория
   `SITE_SSH_KEY`, `SITE_HOST`, `SITE_USER`); атомарная выкладка (папка релиза + симлинк), откат
   на предыдущий релиз одной командой. Сессия создаёт workflow в ветке `feat/site-deploy`,
   в `main` — после зелёного прогона.
5. **Скачивание**: кнопки сайта ведут на последние релизы GitHub (APK, AAB не нужен на сайте,
   EXE и portable ZIP для Windows); проверить, что ссылки и размеры файлов актуальны после
   каждого релиза (скрипт `site/scripts/fetch-releases.mjs`).
6. **Политика конфиденциальности** доступна по `https://www.os-browser.com/privacy.html` и
   `/privacy-en.html` — нужна для Google Play до отправки на проверку.
7. **Почта hello@os-browser.com**: не поднимать почтовый сервер на VPS (1 ГБ RAM, риск спама).
   Подключить почту домена в Beget (MX, SPF, DKIM, DMARC) или пересылку на почту владельца —
   инструкция для владельца, проверка отправкой тестового письма.
8. **Мониторинг и резервные копии**: правило мониторинга Beget «сайт не отвечает» на e-mail
   владельца; снапшот VPS после настройки; проверка свободного места (логротация).
9. **Проверка (приёмка)**:
   - https://www.os-browser.com открывается, все 10 языков, Lighthouse ≥ 95 (производительность,
     доступность, SEO, лучшие практики);
   - SSL Labs — A/A+; securityheaders — A;
   - редиректы http→https и без www→www; 404 работает;
   - автодеплой: тестовый коммит в `site/` появляется на сайте за ≤ 5 минут;
   - вход по паролю и root по SSH отключены (проверить);
   - отчёт со скриншотами.

## Что нужно от владельца (сессия только просит, не решает сама)
- **Пополнить баланс Beget** — в панели предупреждение «На вашем счёту осталось мало средств».
- Добавить в GitHub публичный SSH-ключ, который создаст сессия, или дать сессии доступ через
  секреты репозитория.
- Сделать DNS-записи и почту в панели Beget по инструкции сессии.

## Правила
- Пароли, ключи и токены — только в секретах GitHub или на сервере, никогда в репозитории и в чате.
- Работать в ветке `feat/site-deploy`; в `main` — после проверки.
- Коммиты заканчивать строками Co-Authored-By и Claude-Session своей сессии; модель не указывать.
- Отвечать владельцу по-русски, коротко: что сделано, что нужно от него, готовность в %.
