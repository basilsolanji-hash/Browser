# Сайт Ось Browser — архитектура и техническое задание

Документ для сессии, которая делает официальный сайт Оси. Читать целиком перед работой.
Продукт и правила проекта — в `docs/SPEC.md` (Android) и `docs/SPEC_WINDOWS.md` (Windows).
Прототип главной и страницы «Скачать» — обычные HTML-файлы `docs/site-prototype/index.html`
и `download.html` (открыть в браузере); делать сайт по ним, вид и тексты — эталон.

## 1. Цель и принципы
Сайт — главная точка входа: объяснить, чем Ось отличается, и дать скачать сборку для своей
платформы за один клик. Сейчас платформ две, Android и Windows; в планах iOS (iPhone и iPad)
и macOS.

Сайт должен вести себя как сам продукт:
- **без отслеживания:** ни аналитики, ни cookies, ни сторонних скриптов, шрифты лежат на своём хостинге;
- **быстрый:** статические страницы, JavaScript только там, где он нужен;
- **доступный:** соответствие WCAG 2.2 AA, работа на телефоне, клавиатурная навигация;
- **10 языков**, как в приложении (en, ru, es, pt, fr, de, ar с письмом справа налево, hi, tr, zh);
- **без выдуманных цифр и отзывов:** только проверяемые факты о продукте.
- **не рекламировать лицензии и открытый код** (решение владельца): ни разделов, ни плашек про
  MPL/Apache или open source на сайте; юридически нужные сведения — только в политике и «О приложении».

## 2. Архитектура
```
Репозиторий basilsolanji-hash/Browser
 └─ site/                    ← исходники сайта (Astro + TypeScript)
     ├─ src/pages/[lang]/…   ← страницы по языкам
     ├─ src/components/      ← шапка, карточки, макеты устройств, FAQ…
     ├─ src/i18n/<lang>.json ← тексты сайта (переводы)
     ├─ src/data/releases.json ← генерируется при сборке из GitHub Releases
     └─ public/              ← шрифты, иконки, OG-картинки, .well-known/
GitHub Actions: site.yml
 ├─ на push в main (site/**) и после выхода релиза (workflow_run «Build APK» / «Desktop (Windows)»)
 ├─ скрипт fetch-releases: REST API → последние Android (build-*) и Windows (desktop-*) релизы:
 │    версия, дата, размер, ссылки на файлы, SHA-256 → releases.json
 ├─ astro build → статические файлы
 ├─ проверки (§7) → публикация на GitHub Pages (позже свой домен)
```

**Почему статика на Astro.** Страницы собираются заранее, поэтому на сайте нет сервера, нет базы данных и нечего взламывать. JavaScript по умолчанию нулевой, интерактивные части подключаются точечно («острова»). У Astro встроенная маршрутизация по языкам и отличная скорость. Альтернатива Next.js тяжелее и тянет к серверной части, которая здесь не нужна.

**Ссылки на скачивание и журнал изменений** берутся из GitHub Releases на этапе сборки. Посетитель не делает запросов к GitHub, поэтому нет лимитов API и отслеживания. Каждый новый релиз пересобирает сайт.

**Определение платформы** выполняет маленький скрипт в браузере посетителя. Он по `navigator.userAgentData` или по User-Agent выбирает, какую карточку выделить на «Скачать». Без JavaScript показываются все платформы.

**Хостинг:** GitHub Pages. Политика конфиденциальности уже живёт там: `https://basilsolanji-hash.github.io/Browser/privacy.html`. Её адрес должен продолжать работать (перенос в `site/` с тем же путём или редирект). Свой домен и при желании Cloudflare Pages можно подключить позже (§9).

## 3. Страницы
| Путь | Содержание |
|---|---|
| `/` → `/<lang>/` | Главная: первый экран с выбором платформы, принципы, возможности, профили, конфиденциальность, платформы, FAQ (прототип: Main) |
| `/<lang>/download` | Рекомендуемая сборка для устройства, все платформы, требования, SHA-256, установка, SmartScreen для Windows (прототип: Download) |
| `/<lang>/features` | Подробно по функциям: профили, вкладки и группы, чтение и офлайн, заметки, уведомления, статистика |
| `/<lang>/privacy-security` | Модель угроз простым языком: что хранится и где, защита от трекеров, разрешения, блокировка |
| `/<lang>/business` | Для команд и рабочих аккаунтов (без цен до решения владельца) |
| `/<lang>/changelog` | Журнал изменений из релизов: Android и Windows отдельными лентами |
| `/<lang>/help` | Справка (вопросы и ответы из приложения, `help_q*`/`help_a*`), отзывы по почте |
| `/<lang>/press` | Пресс-кит: логотипы (SVG/PNG), скриншоты, краткое описание |
| `/privacy.html` | Политика конфиденциальности (существующий адрес сохраняется) |
| `/404` | Своя страница «не найдено» |

Первый заход на `/` выбирает язык по `Accept-Language`. Делается это в браузере коротким скриптом с переходом на нужную версию; без JavaScript открывается английская. Выбор языка запоминается в `localStorage`, это не cookie.

## 4. Дизайн
- Палитра из приложения (тема Scarlet Dark):
  - фон `#17181B`, поверхность `#212227`, граница `#33353C`;
  - текст `#ECEDEF`, второстепенный текст `#9BA0A8`;
  - акцент для текста на тёмном `#F0453A`;
  - фон кнопок `#D92D20` под белым текстом (контраст ≥ 4.5:1).
- Светлая тема по `prefers-color-scheme`, цвета из Scarlet Light.
- Шрифты: Unbounded для заголовков, Inter для текста. Оба поддерживают кириллицу; для хинди и китайского — системные шрифты с подстановкой. Файлы шрифтов (woff2, подмножества) лежат на своём хостинге, без Google Fonts на проде.
- Логотип — кольцо «О» на оси с точкой слева и квадратом справа, в SVG. Иконки — линейные SVG, без эмодзи.
- Макеты устройств на первом экране строятся вёрсткой или берутся из реальных скриншотов приёмки, без фотостоков.
- Анимации — короткие появления при прокрутке, с учётом `prefers-reduced-motion`.

## 5. Тексты и переводы
- Тексты сайта лежат в `site/src/i18n/<lang>.json`. Названия функций берутся из переводов приложения (`Tr*.kt`): скрипт выгружает нужные ключи, чтобы сайт и приложение называли вещи одинаково.
- Обязательная проверка в CI: у каждого ключа есть все 10 языков, подстановки совпадают.
- Арабский — `dir="rtl"`; вёрстка на логических свойствах CSS (`margin-inline` и т.п.).
- В FAQ нет ответов, которых нет у владельца: модель распространения, цены и сроки iOS/macOS остаются плейсхолдерами до решения.

## 6. Будущие платформы (iOS и macOS)
- Карточки «Скоро» уже есть в прототипе. Когда сборки появятся, их данные (App Store, файл для macOS) добавляются в `releases.json` тем же скриптом.
- Подготовить в `public/.well-known/`:
  - `assetlinks.json` для Android App Links, если ссылки сайта будут открываться в приложении;
  - позже `apple-app-site-association` для Universal Links на iOS.
- Значки App Store и Google Play — только официальные, после публикации в магазинах.

## 7. Качество и приёмка (обязательно перед каждым выпуском)
- **Lighthouse CI** на главной и «Скачать», мобильный профиль. Пороги: производительность ≥ 95, доступность 100, лучшие практики ≥ 95, SEO 100.
- **Бюджеты:** JavaScript ≤ 30 КБ (gzip) на страницу, LCP ≤ 1,5 с, CLS ≤ 0,05.
- **Playwright:**
  - все страницы на всех языках открываются без ошибок в консоли;
  - кнопка скачивания ведёт на существующий файл (HEAD-запрос к адресу из `releases.json`);
  - определение платформы для Android, Windows, iOS и macOS выделяет правильную карточку;
  - скриншоты на ширине 390, 768 и 1440.
- **axe-core** без нарушений, **проверка ссылок** (lychee), валидный HTML.
- **Заголовки безопасности** (через `<meta http-equiv>` на GitHub Pages, настоящими заголовками на своём домене):
  - CSP: `default-src 'self'`, без `unsafe-inline` для скриптов;
  - `Referrer-Policy: no-referrer`, `Permissions-Policy` со всеми выключенными функциями.
- Результаты прогона публикуются в ветку `site-results` по образцу Android-приёмки.

## 8. SEO и превью
- `hreflang` для всех языков и `sitemap.xml`.
- OG- и Twitter-картинки на каждый язык, генерируются при сборке.
- Структурированные данные `SoftwareApplication` (operatingSystem: Android, Windows; offers — только после решения о цене).
- Понятные `<title>` и `description` на каждом языке, без накрутки ключевых слов.

## 9. Требует решения владельца
- Свой домен (например, ось-браузер или латинский вариант), DNS и HTTPS.
- Модель распространения и цены, раздел «Для бизнеса».
- Почта для связи на сайте (сейчас в приложении `HelpActivity.FEEDBACK_EMAIL`).
- Публикация в Google Play, App Store и Microsoft Store; до неё только прямые файлы.
- Рассылка «Узнать первым» об iOS и macOS. Ей нужен сервис рассылок и согласие на обработку адреса, поэтому без решения владельца кнопка ведёт на страницу релизов.

## 10. Порядок работ
1. Каркас Astro в `site/`, i18n на 10 языков, шапка, подвал, главная по прототипу, деплой на GitHub Pages, сохранение адреса `privacy.html`.
2. `fetch-releases` и страница «Скачать» с определением платформы; журнал изменений.
3. Остальные страницы, пресс-кит, 404.
4. Приёмка §7 в CI, исправления, затем домен по решению владельца.

Коммиты — как в `SPEC.md` §5: в конце строки `Co-Authored-By: …` и `Claude-Session: <url текущей сессии>`, без идентификатора модели. Отчёт владельцу — по-русски: что сделано, ссылка на сайт, результат приёмки, готовность в процентах.
