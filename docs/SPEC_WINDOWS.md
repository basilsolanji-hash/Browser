# Ось Browser для Windows — техническое задание (новая сессия)

Документ для сессии, которая делает настольную версию Оси (пункт №24 «версия для ПК»).
Читать целиком перед работой. Android-версия описана в `docs/SPEC.md`: она эталон
по функциям, стилю и правилам. Здесь только то, что отличается или добавляется.

## 1. Цель
Настольный **деловой браузер с упором на конфиденциальность** для Windows 10/11 (x64),
с тем же набором функций, видом и логикой, что и Android-версия:
- изолированные **профили** (свои входы, cookies, хранилища), у каждого свои вкладки;
- по удобству меню и виду — **не хуже Chrome/Opera**, всё по современным правилам
  безопасности;
- фирменный стиль: алый акцент, логотип «Ось» (кольцо на оси), 6 тем, 10 языков + RTL;
- своих серверов и аналитики **нет**, все данные хранятся на компьютере.

Синхронизация с телефоном **не входит** в задачу: для неё нужен сервер (см. §9).

## 2. Решение по технологии (утверждено в этом ТЗ, менять только с согласия пользователя)
**Electron** (Chromium) + TypeScript, без фронтенд-фреймворка или с лёгким (на выбор
сессии: чистый TS + Web Components либо Preact). Почему так:
- профили — штатные изолированные сессии `session.fromPartition('persist:profile_<id>')`;
  инкогнито — партиция без `persist:` (в памяти, стирается при закрытии);
- вкладки — `WebContentsView` (Electron 30+), по одной на вкладку, в окне с собственным UI;
- готовые API для всего, что есть в Android-версии: `printToPDF` (сохранение страниц),
  `Notification` и обработчик разрешений (уведомления сайтов), `contextMenu`/выделение
  (заметки), `session.setPermissionRequestHandler` (разрешения сайтов), загрузки,
  полноэкранный режим, печать, масштаб;
- сборка, установщик и автообновление: `electron-builder` (NSIS) + `electron-updater`
  через GitHub Releases;
- Windows, macOS и Linux из одного кода (сейчас цель — Windows, остальное потом).

Минусы, которые нужно назвать пользователю: на ПК будет движок Chromium, а не Gecko
(вид и поведение сайтов как в Chrome); установщик около 100 МБ.
Альтернативы (WebView2 + WinUI 3 на C#, Tauri) отклонены: только Windows или мало
возможностей для мультипрофиля и вкладок. Если пользователь захочет Gecko на ПК, это
отдельный большой проект (сборка Firefox/Floorp), в эту задачу не входит.

Версии: актуальные стабильные Electron и Node LTS на момент начала; **точные версии
зафиксировать в `package.json` и `package-lock.json`** (без `^`/`latest`).

## 3. Репозиторий и сборка
- Тот же репозиторий `basilsolanji-hash/Browser`, папка **`desktop/`** (Android не трогать).
  Ветки работы: `feat/desktop-*`, в `main` — после зелёной приёмки.
- Структура:
  ```
  desktop/
    package.json, package-lock.json, tsconfig.json, electron-builder.yml
    src/main/      — главный процесс: окна, профили, вкладки, меню, хранилища, IPC
    src/preload/   — мосты contextBridge (минимальный API для своих страниц)
    src/ui/        — интерфейс браузера: полоса вкладок, адресная строка, экраны
    src/pages/     — свои страницы: старт, настройки, профиль, избранное, загрузки…
    src/content/   — скрипты для сайтов: режим чтения (Readability), выделение текста
    assets/        — иконки (ico/png) и логотип
    scripts/       — генерация переводов из Kotlin (см. §6)
    test/          — приёмка на Playwright (§5)
  ```
- CI: новый workflow `.github/workflows/desktop.yml` на `windows-latest`:
  `npm ci` → проверка типов и линтер → сборка → `electron-builder --win nsis`
  → артефакт установщика. Для `main` — релиз
  `desktop-<run>` с `Os-Browser-Setup-<версия>.exe` (как Android-релизы); для ручного
  запуска на `feat/desktop-*` — пре-релиз (как `build.yml`).
- Подпись кода: сертификата пока **нет** (см. §9). До его появления сборка без
  подписи, и Windows SmartScreen будет предупреждать. Это написать в заметках релиза.
- Ограничения среды (как в `SPEC.md` §2): сборка и приёмка только в GitHub Actions,
  GitHub через `gh` и REST, логи jobs скачать нельзя, поэтому важные шаги пишем в файлы
  результатов (§5).

## 4. Функции и порядок работ (этапы; после каждого — приёмка)
Соответствие с Android указано в скобках (файл-эталон в `app/src/main/java/ru/multibrowser/`).

**Этап 1. Каркас и профили (MVP)**
- Главное окно без системной рамки (своя шапка в стиле Оси), запоминание размера и положения.
- Экран профилей (`MainActivity.kt`): логотип, «Деловой браузер», описание, быстрые
  ссылки (Заметки, Сохранённые страницы, О приложении), первые 5 профилей и кнопка
  «Показать все», порядок перетаскиванием, описание и файлы профиля (`ProfileActivity.kt`).
- Профили 1–50 (`Profiles.kt`), цвет по той же формуле, партиция на профиль.
- Закреплённые вкладки: общий набор и свой у профиля (`Pins.kt`, `PinEditor.kt`);
  открытые вкладки, группы, сетка и поиск по вкладкам (`Tabs.kt`, `TabsActivity.kt`);
  `Ctrl+T`, `Ctrl+W`, `Ctrl+Tab`, `Ctrl+Shift+T` (вернуть закрытую), перетаскивание вкладок.
- Адресная строка: домен с замком в покое, полный адрес при фокусе, подсказки
  из истории и избранного, поиск (по умолчанию DuckDuckGo, `Search.kt`).
- Локализованная стартовая страница с фразой дня (`StartPage.kt`, `Home.kt`).
- Инкогнито-окно (тёмное, отдельная партиция в памяти).
- Первый запуск: обучение и профили-примеры «Личное/Работа/Покупки/Соцсети»
  (`Onboarding.kt`); названия-примеры хранятся ключами перевода `@…`.

**Этап 2. Данные и библиотека**
- История по профилям (`History.kt`), избранное с папками (`BookmarksActivity.kt`),
  загрузки (`DownloadsActivity.kt`), заметки (`Notes.kt`), сохранённые страницы в PDF
  (`SavedPages.kt`, через `webContents.printToPDF`), статистика (`Stats.kt`).
- Очистка данных профиля и кэша, выход из аккаунтов профиля.

**Этап 3. Конфиденциальность и безопасность**
- Защита от трекеров: блок-листы трекеров, майнеров и сборщиков отпечатков (уровень как
  стандартный в Firefox). Брать список с совместимой лицензией (например, Disconnect,
  лицензия CC BY-NC-SA, **проверить** допустимость для бесплатного приложения;
  иначе — EasyPrivacy, GPL/CC BY-SA). Счётчик заблокированного идёт в статистику.
- Сторонние cookies — изоляция по сайтам; режим «только HTTPS».
- Разрешения сайтов и экран настроек сайта (`SitePermissions.kt`, `SiteSettingsActivity.kt`),
  проверка безопасности (`SecurityCheckActivity.kt`), поиск в настройках.
- Блокировка приложения: PIN (обязательно) и Windows Hello (через нативный модуль;
  если надёжного модуля нет — только PIN, сказать пользователю).
- Скрытие содержимого окна при записи экрана: `setContentProtection(true)` по настройке.

**Этап 4. Удобство (D/E/F из Android)**
- Режим чтения: Mozilla Readability (Apache 2.0) в изолированном мире content-скрипта,
  по образцу `app/src/main/assets/reader/reader.js`.
- Выделение текста: «Копировать», «Добавить в заметку», «Поделиться» (в буфер или почта),
  «Поиск» (`PageTools.kt` → `TextActions`).
- Полный экран (`F11`) и полноэкранный режим сайтов.
- Уведомления сайтов → уведомления Windows с именем профиля; нажатие открывает
  вкладку (`Notify.kt`). Push при закрытом браузере не делаем (§9).
- «Браузер по умолчанию»: регистрация ProgId/URL-ассоциаций в установщике и кнопка,
  открывающая `ms-settings:defaultapps` (программно стать браузером по умолчанию в
  Windows 10/11 нельзя, и это нормально); открытие ссылок, переданных при запуске
  (`process.argv`, `second-instance`), с той же фильтрацией схем, что `DefaultBrowser.incomingUrl`.
- «О приложении» (версия, движок Chromium/Electron, лицензии), «Справка и отзывы»
  (письмо на адрес из `HelpActivity.FEEDBACK_EMAIL`).
- Смена языка применяется сразу во всех окнах.

**Этап 5. Выпуск**
- Автообновление через GitHub Releases (`electron-updater`), с отключением в настройках.
- Установщик NSIS: выбор папки, ярлыки, удаление с опцией «удалить данные».
- Портативная версия (zip) — по желанию пользователя.

## 5. Жёсткая приёмка (обязательно после каждого этапа)
- Workflow `.github/workflows/desktop-acceptance.yml` на `windows-latest`: собрать
  приложение, запустить через **Playwright for Electron** (`_electron.launch`), пройти
  сценарии этапа, сделать скриншоты окна и своих страниц.
- Каждый сценарий проверять **по состоянию** (файлы данных в `userData`, URL вкладок,
  открытые окна), а не только по картинке; результаты писать построчно в `checks.txt`
  (`ok …` / `FAIL …`). Любой `FAIL` или пустой ключевой экран роняет приёмку
  (пиксельная проверка — как `blank`-проверка в `.github/scripts/acceptance.sh`).
- Результаты (PNG, `checks.txt`, `steps.txt`, логи главного процесса и консоли страниц)
  force-push в ветку `acceptance-results-desktop`, как у Android-приёмки:
  `git clone --depth 1 -b acceptance-results-desktop https://github.com/basilsolanji-hash/Browser.git <dir>`.
- Обязательные сценарии этапа 1: первый запуск и обучение; создать вкладки в двух
  профилях и убедиться, что cookies не пересекаются (страница на локальном сервере
  ставит cookie в профиле 1 и не видит его в профиле 2); инкогнито не оставляет данных;
  перезапуск восстанавливает вкладки; смена языка.

## 6. Общие ресурсы с Android
- **Переводы — единый источник:** `app/src/main/java/ru/multibrowser/Tr*.kt`. Скрипт
  `desktop/scripts/gen-i18n.mjs` разбирает их и создаёт `desktop/src/i18n/<lang>.json`
  при сборке; новые строки для ПК добавлять **в те же Kotlin-модули** (новый модуль
  `TrDesktop.kt` с ключами `dt_*`, его подключить в `Tr.M` как остальные), чтобы
  Android и ПК не расходились. Ключи с `%d`/`%s` — форматировать так же.
- Темы и палитра: перенести значения из `Themes.kt` в CSS-переменные.
- Логотип: из `res/drawable/ic_wordmark.xml` и иконки приложения сделать SVG/ICO.
- Стартовая страница: тот же текст и стиль, что в `StartPage.kt`.

## 7. Обязательные правила безопасности Electron
1. Для всех окон и вкладок: `contextIsolation: true`, `sandbox: true`,
   `nodeIntegration: false`, `webSecurity: true`. Без `remote` и `<webview>`.
2. Свои страницы — по своей схеме (`os://…`, через `protocol.handle`), со строгим CSP;
   сайтам мосты preload **не выдавать**. IPC: проверять отправителя (`event.senderFrame`)
   и аргументы.
3. Навигация: `will-navigate`, `setWindowOpenHandler` (попапы входа Google открывать
   настоящим окном с opener, как в Android `Popups.kt`; остальное — новой вкладкой),
   запрет `file://` и опасных схем из сайтов, `shell.openExternal` только для `http(s)`/`mailto`.
4. Разрешения: по умолчанию «спросить», запоминание по сайту и профилю, камера,
   микрофон и геолокация — только после явного согласия.
5. Обновления и загрузки — только по HTTPS; проверка подписи обновлений после
   появления сертификата.
6. Никакой телеметрии; отчёты об ошибках — только локальный журнал «Диагностика».

## 8. Соглашения (как в `SPEC.md` §5)
- Все видимые строки — только через переводы (10 языков), никаких строк в коде.
- Стиль кода — как в существующем проекте: короткие комментарии по-русски «зачем»,
  без лишних абстракций.
- Коммиты: в конце `Co-Authored-By: …` и `Claude-Session: <url текущей сессии>`;
  идентификатор модели в коммиты и код не писать.
- Не имитировать сервер. До 3 субагентов — по независимым модулям (например: 1 —
  вкладки и профили, 2 — библиотека и данные, 3 — приёмка), один файл не правят двое.
- Отчёт пользователю — по-русски: что сделано, ссылка на установщик, результат приёмки,
  готовность в процентах.

## 9. Требует решения пользователя (не делать без ответа)
- **Сертификат подписи кода** (EV или OV) для Windows: без него SmartScreen предупреждает
  при установке. Нужна покупка и передача в секреты GitHub.
- **Microsoft Store** (MSIX): нужен аккаунт разработчика.
- **Синхронизация с телефоном** (вкладки, закладки, заметки) и **Web Push** при закрытом
  браузере: нужен сервер, это отдельный проект.
- Движок: подтвердить Chromium (Electron) или заказать отдельную оценку для Gecko.
