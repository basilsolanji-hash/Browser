## 2. Доступ к приложению (App access)
«Все функции доступны без особых условий доступа» — входа в аккаунт Оси нет, у приложения нет
своих аккаунтов. Блокировка по отпечатку отключена, если на устройстве нет блокировки экрана.

## 3. Безопасность данных (Data safety)
- **Собирает ли приложение или передаёт какие-либо из обязательных типов данных?** — **Нет.**
  - Разработчик не получает никаких данных: серверов, аналитики, рекламы, отчётов о сбоях нет.
  - Передача данных сайтам, которые пользователь сам открывает, и выбранной им поисковой системе
    не считается сбором данных приложением (это действие пользователя в браузере).
  - Safe Browsing движка GeckoView отправляет только анонимные хеш-префиксы адресов для проверки
    на фишинг — это не персональные данные; описано в политике конфиденциальности.
- **Шифруются ли данные при передаче?** — Да (соединения с сайтами по HTTPS; режим «Только HTTPS»).
- **Можно ли запросить удаление данных?** — Данные хранятся только на устройстве; удаляются в
  приложении («Очистить данные», «Выйти и очистить», удаление паролей) или удалением приложения.
- Итог в карточке: «Разработчик не собирает и не передаёт данные пользователей».

## 4. Возрастной рейтинг (анкета IARC)
- Категория: **«Утилиты, продуктивность, связь и прочее»**.
- Насилие, страх, сексуальный контент, ненормативная лексика, наркотики, азартные игры — **Нет**
  (в самом приложении такого контента нет).
- **Пользователи могут общаться/обмениваться контентом в приложении?** — Нет (своего чата нет).
- **Доступ к неограниченному интернету (браузер)?** — **Да.**
- **Передаёт ли приложение местоположение пользователя другим пользователям?** — Нет.
- **Покупки цифровых товаров?** — Нет.
- Ожидаемый результат: низкий возрастной рейтинг с пометкой «Неограниченный доступ в интернет»
  (окончательно рейтинг выставляет IARC по ответам).

## 5. Целевая аудитория и контент
- Целевой возраст: **18 и старше** (деловой браузер). Приложение не предназначено для детей,
  поэтому требования программы «Для семей» не применяются.
- Привлекает ли приложение детей непреднамеренно? — Нет.

## 6. Новости, госприложения, здоровье, финансы, COVID
Не является новостным, государственным, медицинским или финансовым приложением — везде «Нет».

## 7. Разрешения — объяснения для проверки
| Разрешение | Зачем |
|---|---|
| `INTERNET` | Открывать сайты (основная функция браузера). |
| `POST_NOTIFICATIONS` | Уведомления сайтов, которым пользователь это разрешил, и ход скачивания. |
| `REQUEST_INSTALL_PACKAGES` | Открыть установку APK-файла, который пользователь сам скачал в браузере, по его нажатию в «Скачанных файлах». В декларации Play Console выбрать разрешённый вариант использования **«Просмотр веб-страниц или поиск» (Web browsing or search)**. |
| `CAMERA`, `RECORD_AUDIO` | Только когда сайт запрашивает (видеозвонки, голосовые сообщения) и пользователь подтверждает в окне разрешения сайта. |
| `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION` | Только когда сайт запрашивает местоположение (карты, доставка) и пользователь подтверждает. Фоновый доступ к местоположению **не используется** — отдельная декларация не нужна. |
| `WRITE_EXTERNAL_STORAGE` (maxSdk 28) | Только Android 9 и ниже: сохранить скачанный файл в папку «Загрузки». |

Видео для проверки разрешений не требуется (нет фонового местоположения, доступа ко всем файлам,
SMS/звонков, специальных возможностей).

## 8. Сборка и подпись
- Формат для загрузки: **AAB** — в каждом релизе на GitHub есть `Os-Browser-build-N.aab`.
- `targetSdk 36`, `minSdk 26` — соответствует требованиям Google Play на 2026 год.
- **Подпись приложений Google Play (Play App Signing)**: включить при первом выпуске. Нашим
  ключом подписывается загружаемая сборка (ключ загрузки); итоговую подпись для пользователей
  хранит Google. Ключ и пароль — у владельца (секреты CI `OS_KEYSTORE`, `OS_KEYSTORE_PASSWORD`).
- `versionCode` = номер сборки, растёт автоматически; `versionName` = 0.8.N.

## 9. Тестирование перед выпуском
1. Внутреннее тестирование (до 100 тестировщиков по e-mail) — сразу после загрузки AAB.
2. Для нового личного аккаунта разработчика Google требует **закрытое тестирование: не менее
   12 тестировщиков в течение 14 дней** перед выпуском в рабочую версию.
3. Затем — рабочая версия (production), можно постепенно: 10 % → 50 % → 100 %.
