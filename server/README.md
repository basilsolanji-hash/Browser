# Панель владельца Ось Browser и основа аналитики

Новая разработка по решениям владельца 07.11.2026. Реализована локально, не развёрнута.
Интерфейс на 16 языках, арабский RTL, широкий и узкий экран. `/admin/` показывает
статистику сервиса и разрешённые сводные счётчики. Нет подставных чисел: без адаптера
синхронизации видны прочерки и явное сообщение о неподключённом сервисе.

Доступ владельца: независимый случайный 32-байтовый ключ из защищённого окружения,
короткие HttpOnly/Secure/SameSite-сессии, CSRF/Host-проверки, ограничение входа, logout
с серверным отзывом. Ключ не пишется в localStorage/журналы. Cookie в production Secure;
отключение Secure доступно только тестовому loopback origin с явным allowLocalHttp.
Неудачные входы ограничиваются временными счётчиками сетевого peer (не более 1024,
TTL 60 секунд), без журналов/БД. Корректный 256-битный ключ проверяется constant-time
и не блокируется чужими отказами даже за общим loopback nginx. X-Forwarded-For и
X-Real-IP от запроса не считаются доверенными источниками личности.
После ожидания асинхронного провайдера сессия проверяется повторно: отозванная или
истёкшая сессия не получает поздний ответ. Интерфейс отменяет/игнорирует устаревшие
запросы, очищает показанные данные при выходе и истечении TTL, перепроверяет их после
возврата на вкладку/BFCache. Ошибка сетевого выхода показывается явно; локальная
страница всё равно очищается, но серверный отзыв при таком сбое не объявляется успешным.
API отдаёт пять разрешённых числовых показателей (включая успешные синхронизации),
строгое состояние healthy/degraded/unavailable и обезличенные агрегаты;
доступа к зашифрованному содержимому личных хранилищ в нём нет.
`npm test` — локальные проверки Node.js 24+, без GitHub Actions и сторонних зависимостей.

Реализовано:
- `UsageQueue`: согласие по умолчанию выключено; отзыв стирает очередь;
  инкогнито не собирается; ограниченные сводные счётчики без URL/текста/идентификаторов.
- Строгая схема: восемь разрешённых функций, Android/Windows, целочисленные счётчики;
  любые дополнительные поля, в том числе личные данные, отклоняются.
- `AnalyticsStore`: SQLite хранит только день, платформу, функцию, счётчик и признак
  достаточного размера группы. Нет сырых событий, аккаунтов, устройств и точного времени событий.
- Публикация группы только после 20 разных согласившихся аккаунтов. Один аккаунт не может
  достичь порога повторными действиями. Для этого проверенный идентификатор аккаунта из
  серверного контекста преобразуется HMAC с ежедневной случайной солью; соль и ограниченные
  множества доказательств хранятся только в памяти. Они не пишутся в БД/журналы.
  После перезапуска неполные доказательства теряются: порог становится строже, не слабее.
- Отчёт выдаёт только завершённые дни UTC. Текущий день скрыт при любом числе участников:
  это исключает наблюдение live-перехода счётчика 20→21. Событие не может задавать день;
  последующая активность не изменяет сводку уже завершённого дня. Период по умолчанию —
  последние семь завершённых дней. Фильтр периода относится к функциям, не к текущим
  показателям сервиса.
- Автоматическая очистка старше 30 календарных дней UTC при записи/чтении. Фоновая
  очистка подключена при старте и ежедневно по UTC; GitHub Actions не используются.

Границы: HTTP-сборщик статистики, авторизация обычных аккаунтов, UI согласия на Android/Windows
и сервер синхронизации пока не подключены. Панель предназначена для чтения показателей;
операции удаления/блокировки пользователей не реализованы. `ingest(batch, context)` — внутренний API:
контекст (аккаунт, актуальное согласие, отсутствие инкогнито) передаёт только будущий
проверенный обработчик авторизации. Признак consent из JSON клиента не считается разрешением.
Наличие этого модуля не включает аналитику в браузере и не разрешает публичный endpoint без проверки согласия.
UsageQueue — пока отдельная модель политики, не подключённая к клиентам. Перед подключением
нужны привязка согласия/очереди к аккаунту и устройству, сброс при смене аккаунта и протокол
подтверждения доставки: текущий drain() извлекает счётчики до сетевого ACK. Ни эта интеграция,
ни надёжная доставка клиентских пакетов не объявляются реализованными.

Проверки: локальные unit/API-тесты и `npm run test:ui` (Playwright) — отказ/отзыв/инкогнито, ограничение очереди, приватные поля,
неверные пакеты, закрытый доступ без контекста, порог 20 участников, разделение групп,
отсутствие идентификаторов в SQLite и удаление старых данных; авторизация/CSRF/Host,
лимит входа, истечение/отзыв сессии, 16 переводов и словарь. Браузерная проверка:
Проверяются 16 языков, 390/1440px, RTL, настоящие агрегаты завершённого дня из тестовой SQLite,
заполненные показатели/состояния сервиса, ошибочный провайдер, поздний ответ после выхода,
сетевой сбой выхода, TTL и возврат страницы из BFCache. Итоговые количества см. в локальном
выводе npm test / npm run test:ui.
Снимки сохраняются в `artifacts/` (не коммитятся).

## Запуск и подготовленная выкладка
Node.js 24+, `npm ci`, затем `npm start`. Обязательны OS_SERVICE_DATA,
OS_ADMIN_ORIGIN (точный HTTPS origin) и OS_ADMIN_SECRET (64 случайных hex-символа).
Публиковать только за существующим HTTPS reverse proxy. Шаблоны — `deploy/`;
реальный env-файл хранить вне репозитория, права 0600. systemd запускает непривилегированный
сервис на 127.0.0.1:8090. Привилегии SQLite-файла/каталога ограничиваются umask 0077.
Ничего на удалённом сервере автоматически не устанавливалось; для выкладки нужен доступ к VPS.
Приёмка авторизации на реальном HTTPS и подключение реальных метрик ещё впереди.
Шаблон nginx должен заменить существующие logging targets HTTPS/default vhost, а не
добавить ещё один error_log рядом с уже действующим: Nginx записывает во все такие цели.
В шаблоне отключены access/error logs на уровне vhost и обоих admin locations, включая
редирект. До выкладки нужно проверить фактический nginx -T: ни дефолтный vhost, ни
reverse proxy не должны сохранять IP/URI ошибок до выбора location. Локальный тест
шаблона проверяет наличие этой политики; он не заменяет проверку конфигурации VPS.
